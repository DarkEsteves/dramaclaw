## 2026-10-15 作品方案请求固定关闭推理

结构与台词、画面与声音两个独立任务共用的 `run_plan_text` 固定发送 `reasoning_effort: "none"`，不再读取 `FREEZONE_PRODUCTION_PLAN_REASONING_EFFORT`。输出预算、截止时间与流式诊断仍按原配置执行；画布操作及动作执行的确认流程保持原样。

修改前，同一现场输入的一次请求约 278 秒返回，输出 14676 token，其中推理 13146 token；临时配置 `none` 后，一次请求约 18.8 秒返回，输出 1655 token，其中推理 61 token。两次上游均自报 `glm-5.3-flash`，且均因阶段结构校验失败而结束。这是两次现场样本，说明推理参数影响明显，不代表方案生成已经成功或所有请求都能达到相同耗时。


## 2026-10-15 恢复单次完整起草

在用户授权的一次隔离实验中，使用同一现场输入、旧单次完整起草提示词及当前模型路由，请求固定发送 `reasoning_effort: "none"`、输出上限 16384 token。HTTP 用时约 50.2 秒，全程约 50.5 秒，上游返回 `stop`，报告底层模型 `glm-5.3-flash`。输出 3338 token，其中上游仍报告 536 个推理 token；发送 `none` 不等于可以保证上游计数为零。

这次返回包含 6 个叙事段落、6 句台词、8 个画面、6 个字幕及 8 个图形，没有独立音频素材。唯一结构错误是 `provenance` 多返回三个字段。离线删除这些额外来源字段后，当前完整方案校验和制作要求检查通过。仍有台词语速与表述一致性需要 Agent 审核，单个样本不能证明稳定性或质量已完全达标。

据此将新起草恢复为一次模型请求生成完整方案，保留已有上下文裁剪、任务进度、保存、审核和确认流程。多余字段仅在模型草稿入口按起草 Schema 递归剔除，不能掩盖缺失字段、类型错误、引用或内容问题；来源信息由宿主填写。请求继续固定关闭推理，不自动重试。历史 outline 的显式补齐动作继续兼容，保留用户修改，但新任务不再自动或强制拆为两阶段。

本次实现的验证使用假 HTTP 响应与已保存实验响应做离线回放，没有追加付费模型请求。
