# 参考视频改编：先看作品方案，再制作素材

## 目标与边界

用户输入改编主题后，首先看到可编辑的整片规划，而不是只有一块台词和含糊的 A-roll 操作。规划要回答：视频要讲什么、每段多长、谁说哪句话、届时画面是什么、声音从哪里来、哪些素材已经就绪。用户确认规划后，才能按段制作或绑定素材，最后进入成片编排。

沿用现有 `production_plan.v1` 草稿、保存、编译能力，不另建一套与它竞争的脚本格式。继续支持已有 `remix_script.v1` 项目，不静默改写或删除它们。此阶段不承诺凭规划自动生成准确口型；口型由后续选择的出镜素材/生成能力决定。

## 方案选择

- **采用：把作品方案接成默认改编入口。** 新项目从原片分析点击“开始改编”后创建或打开作品方案；旧脚本提供显式转换入口。这样规划与后续编排共用同一份数据，不会让用户在两个脚本界面之间猜测。
- 保留旧面板并在顶部补一个“整体规划”摘要：改动小，但仍要维护两份事实来源，A-roll/B-roll 与成片编排可能不一致。
- 另做独立向导：步骤清晰，但会引入第三套状态与同步，当前阶段不需要。

## 用户流程

1. 原片分析节点的“开始改编”打开一个作品方案。输入新主题后点击“生成整体方案”。AI 返回按叙事目的划分的段落，包含时长、台词、主画面、切入/补充画面、旁白或同期声的意图。编辑前不生成素材，也不扣除媒体生成费用。若无可用原片分析，仍可依据主题起草。
2. 面板顶部先显示一句话目标、总时长、段落数，以及每段的简明卡片。卡片先读得懂“讲什么 / 谁说 / 观众看到什么 / 听到什么 / 缺什么”，再展开精确时间与素材绑定。每段的台词、画面描述、声音描述和时长均可改。
3. 对每个有台词的段落，显式展示“出镜口播”或“画外旁白”：前者要求主画面有人物出镜且说话，后者允许画面为产品、场景或 B-roll。界面从 `speech`/`narration` 声音角色给出选择和说明，不把“整段配音”误称为 A-roll。主画面必须连续覆盖段落；中途切入的全屏镜头也是分时段的主画面，`overlay` 只用于叠加画面。
4. 每个画面/声音需求可选择已有画布素材，或从该需求创建对应的制作节点；新节点带上段落描述与台词作为初始制作信息，仍由用户决定何时生成。未绑定、已绑定、素材版本过期都明确显示。所有主画面和必要声音就绪后，用户进入成片编排；未就绪时指出具体段落与缺项，不建立半成品成片节点。
5. 对已有旧脚本，原入口继续打开旧稿，提供“转为作品方案”按钮。转换创建新方案节点并保留旧节点/产物；主题、说话人和每句台词原样带入。AI 可以补充段落安排与画面声音描述，但不得擅自改写现有台词；转换失败时旧稿仍可用。已有方案优先于旧稿作为下次“编辑作品脚本”的入口。

## 数据与接口

- 前端只维护一份当前 `production_plan.v1` 草稿，编辑与 AI 结果通过现有产物 API 保存为明确修订版；成片编排仍通过现有编译 API，从所保存的修订版生成清单。
- 草稿接口接受可选的旧台词约束。服务端校验 AI 返回的说话人与台词顺序逐句保持一致；不满足时拒绝结果并保留用户当前草稿，界面允许重试或手动调整。无旧稿的新改编则可自由起草。
- 画面/声音制作节点与方案需求的关联通过现有画布连线及绑定媒体哈希实现。节点初始描述是制作提示，不等同于已生成素材。绑定时继续检查媒体类型、版本和时长。
- 旧脚本的 `remix_script.v1` 与它的媒体节点原样保留；不在加载项目时自动迁移。转换动作必须可重复调用而不创建重复方案节点。

## 错误与验收

- AI 失败、返回结构错误或违背旧台词约束时，保持用户已编辑的方案不变，给出可重试的明确错误。
- 空目标不发请求；超 60 秒、主画面覆盖有空档、素材缺失或版本过期时指出对应段落和需求，阻止进入编排。
- 测试覆盖新入口只创建一份方案、已有方案复用、旧稿显式转换且台词逐字保留、AI 失败不覆盖草稿、A-roll/旁白标签与素材状态、节点制作与绑定、编译前缺项提示及成功进入编排。
- 前端遵循现有 `DESIGN.md` 变量与组件样式；本设计不修改视觉 token。
