# 画布作品方案与视频合成统一工作台设计

日期：2026-10-09
状态：设计稿，待用户审阅后分阶段实施

## 1. 目标与已确认的产品规则

用户从原片分析或创作目标进入作品方案，用 AI 起草或自己编辑叙事、台词、画面、声音与动效需求；从作品方案直接进入现有视频合成节点，在同一套全屏工作台上剪辑、预览和导出。画布只显示「作品方案 → 视频合成」这条下游连接。素材节点向作品方案提供可追溯的输入。

Hypit 的 SVML 与 Studio 是设计参考，不作为本项目的语法、运行时或 UI 依赖。我们以版本化的结构化数据表达同类关系，视频合成器是这份数据的可视化编辑界面。

本文是后续实施的统一目标；与较早的改编计划、2026-09-29 和 2026-10-08 方案相冲突时，以本文已确认的直连流程、输出规格和单一作者数据规则为准。当前代码仍有专用的 `production_compose` 展示与中间编排入口，不能把本设计表述为已上线能力。

用户没有要求固定 9:16、30 fps、60 秒或 40 个叙事段。旧改编 MVP 中的这些限制不进入新契约。作品可为横屏、竖屏或其他画幅，帧率和时长由作品设置与内容决定。编码器确有约束时应在导出目标上明确报错或提供转换建议，不能截断内容或暗中改动作品规格。

## 2. 三种实现方式与选择

| 方式 | 结果 | 决定 |
| --- | --- | --- |
| 视频合成节点只查看由方案生成的清单 | 实现较快，但用户无法在原有工作台剪辑 | 不采用 |
| 合成器保存独立副本，方案另行保存 | 容易出现两个版本的台词、素材和时间 | 不采用 |
| 方案保存可编辑源数据，合成器投影并回写该源数据 | 编辑器与 AI 操作同一版本；需要明确的回写与并发契约 | 采用 |

合成清单属于可重建的渲染输入，不充当第二份用户原稿。已有手动视频合成项目不依赖作品方案，仍使用同一全屏界面；它们的作者数据保存在合成草稿中。两类项目共享编辑器和新合成模型，内部保存入口可以不同。

## 3. 画布节点与用户流程

1. 原片及其分析结果可连接作品方案。作品方案可从空白目标创建，不强制依赖原片，也不按原片事件或每句台词机械分段。
2. 人或 AI 编辑作品方案。每个素材需求可选择现有画布素材，或创建新的生成／上传节点。选择时建立「素材 → 作品方案」边，并记录素材精确版本。仅有需求描述不代表素材已完成。
3. 点击「进入视频合成」时，保存方案当前修订，创建或复用直接相连的现有 `videoComposeNode` 类型，打开原有全屏编辑器。节点元数据记录方案 ID 和修订；不为方案另造一种视频合成节点或简化版弹窗。后台将方案投影为可编辑轨道；这个投影动作不新增画布节点或额外确认页面。
4. 未完成的素材在轨道上显示占位片段和缺项原因。用户仍能查看编排、调整时间并绑定素材。依赖缺失的预览区域要说明缺失内容；最终导出只在所需素材和引用版本有效时放行。
5. 用户在合成器里剪辑、换素材、移动图层、改字幕或动效，界面即时更新并自动保存。回到作品方案可看到同一份修改。
6. 预览与导出使用明确的方案修订、素材哈希和效果版本。任何输入变化使旧预览标为过期；旧 MP4 作为历史结果保留，直到新成片成功发布。

旧的「成片编排」节点不再由新流程创建。现有项目迁移时先确认该节点的修改已保存回方案，再建立「作品方案 → 视频合成」边；保留其产物和旧视频的历史引用。迁移完成后从画布隐藏旧中间节点，不静默丢失独有编辑数据。已有 remix_script.v1 项目继续可读，只有用户显式转换时才建立新方案。

## 4. 统一的作品数据

新增 production_plan.v2 作为方案关联作品的作者数据；production_plan.v1 保持可读，并通过显式、可重复的迁移生成 v2 修订。v2 使用稳定 ID 和类型化引用，不引入 SVML 文本语法。

| 部分 | 保存内容 |
| --- | --- |
| output | 宽、高、以分子／分母表示的帧率、背景与导出目标；均由用户可编辑 |
| beats | 顺序、叙事作用、估计或已确认的时段；一个段落可容纳多句台词、多位说话者或没有台词 |
| turns | 稳定台词 ID、说话人、文本、可选的实际语音／逐词对齐引用 |
| resources | 画布节点 ID、项目媒体路径、内容哈希、媒体类型与精确修订；效果组件 ID、版本与所需资源槽位 |
| placements | 稳定条目 ID、用途、轨道、素材或效果引用、出现时间、源素材入出点、画面位置与动效参数 |
| provenance | 来源分析和用户保留／替换规则的精确引用，以及最后修改的作者与修订 |

placements 是跨段的统一编排表，允许一条 BGM、字幕样式或图形效果跨越多个叙事段。每个条目可关联 beat、turn、word 或另一条目，不必硬塞进某一个 beat。画面角色至少区分主画面与叠加画面；声音角色区分同期声、旁白、音乐与音效。字幕由台词和对齐结果生成后仍可单独编辑。

时间关系提供三种形式：语义锚点加帧偏移、显式节目帧位置、与素材源内时间范围。语义锚点可以指向段落、台词、词或其他条目的起止边界；引用必须存在且无环。音视频源内裁剪与输出时间独立存储，变速只改变两者映射，不篡改原媒体时间。精确逐词对齐存在时，编译器才把词锚点落到具体帧；缺少对齐时显示估算或待定位状态，用户也可设置明确的手动帧位置。画布显示的预计时长不冒充已校准的实际语音时长。

所有在合成器中提供的操作必须能回写到 v2 源数据。新增片段会创建 placement；拆分创建新的稳定 ID 并保留源范围；拖动已锚定条目优先修改锚点偏移，用户选择解除锚定时才改为显式帧位置；素材替换更新资源引用和画布连接；画面、声音、字幕与关键帧修改保存到对应条目。不能表达的操作不应在界面中伪装为已保存。

## 5. 从方案到精确时间线

编译服务读取一个精确的 production_plan.v2 修订、相关对齐产物、画布绑定与素材哈希，生成 composition_manifest.v2。该清单包含具体输出帧、轨道顺序、源内裁剪、变速、画面布局、效果参数、字幕和音频事件。每一行保留来源 placement ID，供编辑器定位及错误反馈。相同输入修订应生成同样的清单；无效或缺失输入返回条目级错误，不发布半成品。

视频合成器读取该投影，但不把它作为唯一保存位置。用户编辑时通过基于稳定 ID 的命令更新方案，提交需要 expected_revision；服务端验证整个修改并返回新修订。前端先本地显示编辑结果，再按顺序自动保存。若 AI 或另一个窗口已经修改源修订，停止覆盖并显示具体冲突，允许比较后保留当前值、接受新值或人工调整。保存失败保留本地未提交草稿及明确状态。导出必须固定到已保存修订，不读取仍在输入中的局部草稿。

没有关联作品方案的手动合成项目使用 composition_timeline.v2 保存同一编辑器模型。现有视频／音频草稿可映射到它；旧草稿和旧导出入口在新模型达到裁剪、变速、音量、封面、撤销重做等能力对等前继续可用。

## 6. 视频合成工作台

沿用原有全屏合成器、播放器、剪辑工具与导出入口。依据项目 DESIGN.md 使用暗色背景和现有颜色、间距与字号变量；借鉴 Hypit Studio 的信息分区，不复制其亮色外观或项目专用轨道名称。

- 左侧是当前画布可用素材及效果库，显示缩略图、时长、已绑定／待生成／版本已变化状态。可选择素材绑定到方案需求，也可拖到轨道创建新 placement。
- 中间是随作品宽高比变化的合成预览。选中叠加画面、字幕或效果时可直接拖动与缩放，显示安全区域和对齐辅助线。
- 右侧是随选择变化的属性栏：内容、源片范围、时间关系、画面位置、动效、字幕、声音。所选片段可定位回方案中的原条目；效果仅显示组件声明可编辑的参数。
- 下方是可调整高度、可折叠轨道的时间线。方案项目顶部显示叙事段和台词锚点，其下依次是主画面、叠加画面、字幕、效果、人声、音乐／音效。手动项目不显示方案语义轨。轨道显示素材缩略图、音频波形、清晰的名称和缺项状态。

常用动作仍放在顶部工具栏；片段专有属性集中在右侧。修改即时反映预览并自动保存，保留撤销重做。语义轨与素材轨是同一时间轴的两种视图，不创建第二个画布节点。

## 7. 动效与 HTML 效果

基础动效作为 placement 的类型化参数保存：入场、持续、退场，及位置、缩放、旋转、透明度等关键帧。预设只是写入这些参数的快捷方式；之后仍可逐项修改。叠加轨允许与主画面同时存在；转场有明确的前后素材、时长和声音交接规则。字幕效果也以版本化样式与逐帧时序表示。方案可先写动效意图，合成器再细调到关键帧并回写。

HTML 效果通过版本化组件注册：组件 ID、代码／资源哈希、参数 schema、输入素材槽位、透明画布范围和逐帧 render(frame) 契约。作品方案只引用组件和参数，不内嵌任意 HTML 源码。第一批支持独立图形／文字覆盖层；需要把源视频放入组件内部并一起变形的场景效果作为后续独立扩展。未知或失效的组件保留条目并阻止该效果导出，不能悄悄跳过。

现有 FFmpeg 合成负责常规视频、图片、字幕、基础动效、音频混合与最终编码，同时补齐源内裁剪、变速、空间叠层和灵活输出规格。HTML 覆盖效果由受控浏览器按节目帧时钟渲染透明帧，只渲染其实际出现区间，再作为上层输入参与最终合成；不得依赖真实墙钟时间、外网资源或未声明的本地文件。预览与导出使用同一组件版本和参数，关键时间点通过后端抽帧比对。长时作品按片段流式处理，不因临时帧数据而一次性占满内存。

## 8. 多租户执行与浏览器渲染性能

浏览器动效是后端渲染任务，不依赖用户页面保持打开。没有 HTML 效果的作品不启动浏览器，继续走普通 FFmpeg 合成。第一批只允许运行经过注册和版本固定的可信效果组件；AI 或用户提交的任意 HTML／JavaScript 不直接进入渲染器。若以后开放自定义代码，须先完成不可信代码隔离和租户间读取、网络访问的验证。

渲染任务输入是一份不可变的包：方案修订、效果组件版本与哈希、素材哈希、出现帧区间、输出规格。工作节点只按租户及项目授权取得这些资源，不接受任意本地路径或远程 URL。当前 `remix_render` 任务属于 `ffmpeg` 队列、要求 home node 并读取项目目录；跨机器执行前须补齐资源暂存与授权传输契约，不能把本地路径当作分布式协议。

浏览器帧任务使用独立的资源队列和容量预算，不与普通 FFmpeg 导出共用无限制并发。多租户部署在每项任务的隔离执行环境中启动浏览器，使用独立临时目录、最小文件权限、无项目外文件挂载、默认无出站网络、无主服务密钥；运行环境还须启用浏览器自身的沙箱。浏览器 context 可隔离缓存和 Cookie，但不能独自作为不互信租户的安全边界。任务结束或取消必须清理浏览器进程树与临时资源。单租户本地部署可使用同一接口的轻量执行器，但产物和结果语义一致。

调度同时限制租户／项目活跃任务、全局浏览器进程数、单任务 CPU、内存、临时磁盘与运行时间；超过当前容量时排队并显示进度，不把固定作品时长当作资源控制手段。每次只处理 HTML 效果实际出现的帧区间，并按有界片段或流把透明画面送入 FFmpeg，避免把整部作品的 PNG 帧都留在内存或磁盘。预览按需渲染并缓存选定帧；正式导出固定所有输入版本。缓存键至少包含效果代码、参数、素材哈希、帧区间、画幅、帧率与浏览器版本，租户间不共享可读的私有资源。

上线前用横竖屏、长短作品和两租户并发样片测量冷启动、每秒处理帧数、峰值内存／临时磁盘、取消后的清理、缓存命中率及预览／导出画面差异；据实测选择透明帧的流或中间编码方式和默认并发。测试须证明跨租户素材不可读，任务失败不会把未完成画面当成成功导出。

## 9. 兼容、失败与验收

production_plan.v1、composition_manifest.v1、remix_script.v1 和旧手动合成草稿继续可读。迁移创建新修订或新格式草稿，保留原引用、历史视频与回退路径。新合成协议的能力上线前，不把老项目强制送进尚未对等的渲染路径。原有裁剪、变速、音量、封面、撤销重做和导出均需回归。

关键验收场景：

1. 横屏及竖屏方案、不同帧率和超过 60 秒的作品可完整保存、预览与导出；不会静默裁剪，亦无任意段落数上限。
2. 一段包含多位说话者与多个画面；一段无台词也有效。B-roll 锚定台词后，实际语音对齐变化会更新其时间，手动偏移保留。
3. 未绑定素材可进入合成器并显示占位；缺失或版本变化阻止当前版本导出，并定位到具体条目。
4. 合成器内移动、裁剪、换素材、改字幕、加效果后，作品方案相应条目自动更新；关闭重开、AI 读取与再次编译得到相同结果。
5. AI 与用户并发改同一修订时不覆盖对方；冲突可定位到稳定条目与字段。
6. 原手动合成项目打开、编辑、导出结果与旧能力一致；迁移前的视频可继续查看。
7. HTML 覆盖效果在指定帧出现、退出，预览与导出画面一致；未知组件和缺失资源给出明确错误。
8. 新画布只出现「作品方案 → 视频合成」，点击后进入同一全屏编辑器。
9. 两个租户同时渲染不同效果时互相读不到素材，资源耗尽只使对应任务排队或失败，取消后浏览器与临时资源被回收；无 HTML 效果的导出无需浏览器。

## 10. 分阶段实施与每步交付

1. **契约与兼容底座**：建立 v2 数据、迁移、稳定 ID、语义锚点解析及输出规格传播；去掉旧改编路径中 9:16／30 fps／60 秒等硬编码与静默截断，保留旧格式测试。明确不可变素材引用，使后续渲染可脱离 home node 的项目本地路径。此步交付可读写的方案与可验证的编译结果。
2. **直连与统一界面**：作品方案直接创建或复用视频合成节点，原全屏编辑器加入素材栏、属性栏、可调整时间线和方案语义轨；旧中间节点迁移。此步可打开未完成方案并检查占位，不以渲染成功伪称完成。
3. **可编辑轨道与回写**：图片、视频叠加、字幕、音频共享一套编辑模型；编辑命令按条目 ID 自动保存回方案，处理并发冲突。补齐后端叠层、裁剪、变速和灵活规格导出。此步交付从方案到可修改 MP4 的完整链路。
4. **动效与效果组件**：先加入无需浏览器的关键帧、预设和转场，再用一个已注册的 HTML 透明覆盖组件验证逐帧渲染。接入多租户隔离、独立容量控制、按有效区间分段处理和取消清理后，才开放其生产导出；完成预览／导出关键帧及跨租户验收。
5. **虾导操作契约**：提供读取方案、修改条目、创建与绑定素材、检查缺项、编译、预览和导出的稳定 API／工具说明。虾导使用与界面完全相同的校验和修订规则，再编写对应 skill。

每一步均有聚焦的契约测试和用户可见验收；只有该步涉及的旧功能回归通过，才替换其旧路径。本文是设计与实施顺序，不代表上述能力已完成。
