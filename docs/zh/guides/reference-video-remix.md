# 参考视频复刻：虾导与画布制作流程

内置「参考视频复刻」Skill 2.1 使用画布已有的原片拆解、作品方案、媒体节点和视频合成。一个原片可以产生多个独立方案。方案保存目标台词、素材使用关系、字幕、图形和语义锚点；素材工作包记录这些最终素材如何制作。

```text
提供参考视频 → 联合分析 → 确认复刻方向
  → 起草或直接编辑作品方案 → 审核并确认内容
  → 规划参考与中间素材 → 制作、审看、绑定最终素材
  → 有台词时校准实际原声 → 合成与检查 → 按请求交付
```

## 一次起草完整作品方案

1. Agent 用自然语言与用户聊清方向，确认后写入作品方案节点。
2. **AI 起草作品方案**：创建一条任务，一次模型请求生成段落、台词、画面、必要的声音及字幕图形，校验后保存完整可编辑方案。
3. 用户或 Agent 审核、调整方案，沿用原有内容确认流程，再制作素材与合成。Agent 负责方向、审核和执行，无需在对话中起草整份详细方案。

画布操作和动作执行继续使用原有确认机制，不新增确认卡。失败不自动重试、不自动换模型或补发修复请求；任务中心保留进度和失败原因。默认总预算为 540 秒、输出上限为 16384 token，沿用已有执行配置；请求固定发送 `reasoning_effort: "none"`，不再由环境变量控制推理。

模型额外返回的字段会在草稿入口忽略，来源凭据由宿主填写。已知字段的缺失、错误类型、无效引用和制作要求仍会校验；不会把有问题的内容标为成功。人工编辑与已保存方案的校验保持原样。

历史上已经保存的结构与台词可继续通过 **AI 安排画面与声音** 补齐，读取最新方案并保留人工修改；新起草不再走这两步。带声视频可以承载台词及音效，无需默认另建人声音轨；无台词作品也可直接起草完整方案。

## 开始前准备

- 将参考视频上传到项目画布，或明确指定已有视频节点。
- 配置可用的文本/视觉网关；生成素材需要相应的图片、视频或音频模型。具体参考输入和请求时长以所选模型的能力为准。
- 自动语音识别使用已配置的 `audio-transcribe` 网关，见 [NewAPI 语音转写配置](../../experiments/reference-video-remix-speech-setup.md)。无台词作品不需要语音校准。
- 本机合成需要可用的 `ffmpeg` 和 `ffprobe`。服务器部署继续使用现有项目授权、任务队列和媒体存储。

作品分辨率、帧率和时长由方案设置与实际采用的素材决定；这条原生制作流程不限定竖屏、30 fps 或 60 秒。当前不生成 HTML 动画，字幕和图形使用现有原生合成能力。

本地开发启动：

```sh
uv run novelvideo api --port 8780
# 另一个终端
cd frontend
pnpm dev
```

## 使用虾导完成复刻

### 1. 分析参考，确认要保留和替换什么

在虾导选择「参考视频复刻」Skill，指定参考视频和目标。未提供视频时，虾导会请求上传或选择，不凭文件名编造分析。

分析联合实际媒体证据、整段转写（有人声时）和叙事结果。虾导先说明开场、推进、结尾、画面与声音的关系，并针对疑点查看源帧。采样未覆盖的动态过程会保留为未知项。有音轨但没有人声也可以继续。

原片分析事件和关键帧窗口是理解原片的观察证据，不等于复刻视频必须生成同样数量的镜头。事件数量可以作为导演编排参考；Agent 应根据新目标、台词、动作、反应和节奏重新决定镜头数量与组织方式，可以相近、合并、拆分、跳过或重组。对用户复述分析时称为“原片分析事件/证据窗口”；如果提出复刻镜头数量，应说明这是新目标下的导演编排决定。原片的单段时长只用于观察节奏，生成素材仍按每步 4～15 秒及模型能力规划。

虾导用普通对话整理保留的表达方式、替换的人物/产品/台词，以及是否直接采用原素材。讨论和修改意见不会逐轮保存正式方向；用户明确要求推进时，虾导把完整目标交给作品方案节点的原生准备入口，由服务端核验真实对话。创建节点和起草动作仍遵循画布现有确认设置。原片事件可以编辑，无须逐条「点击核对」才能创建方案。

### 2. 编辑并确认真实作品方案

虾导先将概括的完整目标写入原生作品方案节点，由节点 AI 起草详细段落、台词、素材位置和锚点。虾导读取真实保存结果后审核并局部修正。

在作品方案节点点击「编辑作品方案」。使用「方案与素材」修改内容与素材；「台词主线」查看语音与镜头/字幕的语义关系。修改自动保存。方案审核涵盖方向、台词、叙事、声画角色、素材制作、原生效果、输出和锚点，然后请用户确认实际内容。

在方案中先指定每句台词由哪份素材发声。同一条带声视频可以承担连续的多句台词，无须为每句另建音频；B-roll 覆盖说话画面时，原人声仍归原表演素材。需要独立旁白或替换配音时，才选择单独的声音来源。普通视频可选择「使用视频声音」来保留环境声或动作音效；静音画面保持关闭。未决定的来源会显示为待选择，不会凭描述文字自动猜测或删掉旧声音项。实际视频内混合的人声、音乐和音效不能仅凭标签分离，若需单独替换或调音，应规划真实的独立素材。

起草 AI 安排内容、语速意图和节奏；普通口播段缺少时长时，宿主在保存新草稿前用本地字符/音节估算填入预览时间。方案读取和编辑结果附带逐句测时与诊断，过密台词给出警告，明确无效的图文区间阻止审核通过。估值不会覆盖已有人工时间，也不是实际 SRT 或模型发声保证；生成并采用素材后，字幕和跟随台词的画面仍按真实语音时间对齐。无台词段和固定节奏段由 AI 或用户明确安排时长。

发声素材先有自己的段落或片段时间范围，台词再指向这份素材；字幕、图形和不承担该台词发声的画面可以跟随台词。发声素材不能反过来以自己承载、尚未定时的台词定位，即使经过其他画面或选择范围间接引用也不行。同段有多份发声素材时分别安排范围；已有人工时间及采用素材后的真实语音时间保持有效。方案起草若违反时间关系，任务中心会标出相应素材、台词和起止位置；方案不会保存，也不会自动重试。

工作流草稿审批表示同意建节点或执行任务；它与生成后的方案内容确认分别记录。台词、叙事等创作内容发生变化时需重新审核；素材绑定和时间校准保留未改变内容的原确认。

草稿选择“创建并运行”时，批准一次就会在落图后提交方案起草，后续等待任务结果即可；选择“只创建”时，方案节点落图后仍可单独点击起草。任务受理只表示已提交，方案内容仍需生成后审核。

起草默认给单次模型请求 16,384 个输出 token；配置了其他合法额度时沿用配置。完整返回会继续校验，明确截断、格式错误或业务校验失败会停止并在任务日志保留诊断，不自动重发模型请求或产生半成品。需要再起草时由用户通过现有动作明确发起。

多个方案分别拥有方向、审核、素材和交付进度，不会覆盖同一原片的其他方案。

### 3. 按制作依赖补齐素材

虾导先规划素材工作包。例如三个最终视频可以共用人物图、产品图和场景图，也可以由一条多人视频承担多句台词。生成中间素材的数量不等于最终方案的素材数量。

规划时先查看已保存的关键帧和其他项目图片；需要保留人物/产品外观时，应给素材要求绑定有据可查的图片参考，不能删除引用后按纯文字生成。旧方向若没有视觉保留决策，生成素材前会要求沿用现有方向修订与方案复审流程核对，已保存方案不因此自动重起草。每个视频生成步骤单独填写 4～15 秒整数时长，并满足所选模型实际支持范围；短成片镜头可从较长素材中选用，多个镜头也可共用一个素材。方案总时长和每段成片使用长度不必是这些生成时长的总和。

需要图片或视频生成时，沿用现有参数选择界面确认实际模型、画幅和分辨率；仅使用已有素材时不要求选生成模型。推荐值可以预填，但没有用户提交的参数回执时，不能把推荐值当作确认。素材步骤与已确认参数不一致时先修正或重新选择，工作流不会自行改模型。生成前读取当前模型能力；合法时长、分辨率和参考模式没有交集时返回具体冲突。

工作包显示制作步骤、依赖、待上传项和候选。用户提供素材后，可在待补项中选择对应的画布节点；系统校验真实媒体与版本，再进行审看。生成步骤通过现有工作流审批与任务执行。

提交素材工作包时，系统按方案里的发声归属核对 requirements、steps 和最终素材来源：带声说话视频可一次承担多句台词，独立配乐和额外音效各自准备；纯画面和不使用视频原声的 B-roll 无须因此额外生成声音。需要声音的生成视频会要求所选模型支持带声，明确选择静音或模型不支持时保留能力冲突，等待修改制作策略，不擅自更换模型或增设付费配音。

任务完成只表示产物已生成。技术检查验证文件、轨道和时长，内容检查验证用途和验收条件。图片与视频帧检查不能证明实际发音或所有动作；无法观察的项提供用户审看。只有通过检查的最终候选才绑定到方案。

当前选定的素材工作包分别展示「已生成」「检查中」「待审看」「需返工」「已采用」。已完成的候选会保留真实产物；登记或通知失败时恢复原结果，避免重新付费制作。素材可用与已采用分别计数，历史候选和旧工作包不增加当前待办。

局部返工保留原候选和独立合格步骤，只失效失败步骤及其依赖。

### 4. 有台词时校准完整发声素材

目标台词以确认的作品方案为准，时间以实际采用素材为准。同一条多人视频按一次完整源识别，在明确顺序内分配给各句；不按段落预计时长截掉尾部。

技术检查通过的候选可以先做完整素材识别，集中展示目标台词、原始 ASR、差异和真实逐词时间。虾导可以读取差异并提出校正建议；原始观察保持不变。用户在素材审阅中试听并保存实词校正，保存校正不会替用户接受素材。方案台词变化后，需要按新版本重新审阅。

素材正式采用并绑定后，系统可复用同一源观察和有效校正，将词句映射到当前发声素材。采用映射不再重复识别同一完整源，也不代表自动审听通过。共享多人素材保留已声明台词顺序和真实停顿，实际语音超过原预计段落时长时也保留完整发声。

逐词校正显示原识别、修改后的文字、实测时间和对应台词，保留原始 ASR。标点等规范化差异可以直接匹配；错字通过有证据的纠正修复。当前尚未接入可供 Agent 试听并判断的音频审查适配器，因此实词修改需要用户试听并一次确认，Agent 不会把文字匹配冒充原声验证。

仅使用视频环境声或音效而没有台词时，不执行人声识别；选择视频原声也不会自动证明内容审核通过。说话视频绑定后同源多句共享一份发声实例，画面覆盖不会使人声中断或重复播放。

实际漏说、说错或角色不对，需要返工素材或明确修改方案。不能用补 SRT 假装原声已有发音。只有句级时间时可以安排句级关系，词级效果需要真实词时间。

「随台词」编排使用实际句词锚点推导镜头、字幕、声音和段落长度，保留源中的停顿。无台词段落按素材长度或明确时长编排，无须生成空 SRT。

### 5. 合成和交付

合成使用当前方案、已接受素材和有效语音证据。进入视频合成后仍可编辑；上游改变时旧清单或导出不能当作当前结果。

交付范围有四种：仅作品方案、可编辑合成、预览成片、导出成片。仅方案在内容确认后完成；可编辑合成提供当前工作台检查；预览/导出需产生实际视频并检查文件，页面提供播放和整片审看确认。

## 进度、确认和恢复

虾导制作进度卡显示真实阶段、当前决定和待补工作。方向通过普通对话讨论，在原生节点准备时核验真实用户回合；作品方案的内容审核与确认沿用现有流程。画布命令和动作执行仍使用已有确认机制，不增加方向卡。

进度以当前选定的作品方案与素材工作包为准。多个独立方案分别读取、推进；存在历史工作包时，需要明确选择当前工作，不能按最新时间替换。虾导使用 `freezone_get_production_progress` 一次读取当前计数、执行状态、阻塞项与下一步；确定性的系统动作通过 `freezone_advance_production` 按同一投影版本核对后推进。新付费制作仍沿用工作流审批，创作选择和无法自动核实的声音仍等待用户确认。

已保存方向、模型参数与预算继续复用，不因断线重复询问。等待执行、等待用户、版本冲突、结果登记、内容不可审查和供应商失败各自保留具体原因；失败不会统一转成「重新生成」。停止后保留结果，等待用户明确继续。用户自定义 Skill 的版本和启用状态继续优先，不会静默升级或覆盖。

完成或重连时优先读取保存的分析/方案，查看读取来源、版本、coverage 和实际回执。`requires_browser`/`no_connection` 只说明动态选择、未保存编辑或浏览器执行需要打开对应画布；已保存内容继续可读。读取或通道失败保留原任务与分析，用“继续处理”恢复当前阶段，不重新分析原片。版本冲突先保护用户正在编辑的内容，读取最新版本后只应用已授权修改。

长任务提交后结束当前 Agent 回合。宿主观察已保存任务结果和阶段变化，在有意义的完成点通知并继续，Agent 不持续查状态。关闭页面后结果仍保存，重开可继续；断线不应导致重复付费生成。

| 问题 | 处理方式 |
| --- | --- |
| 参考片未指定或选择不明确 | 上传实际视频或明确选择节点。 |
| 无音轨、无台词 | 继续分析画面和编排，跳过语音校准。 |
| ASR 错字 | 展开逐词差异，试听并一次校正应用，保留真实词时间。 |
| 素材真实漏句 | 返工该素材，或明确批准修改目标台词。 |
| 图片/声音参考缺失 | 在具体待上传项关联画布素材，继续其依赖步骤。 |
| 候选不合格 | 保留候选，局部重试受影响步骤。 |
| 方案版本冲突 | 读取最新方案并重新应用必要修改，保护用户正在编辑的内容。 |
| 合成/导出已过期 | 用当前版本重新编译；未变的素材与识别结果继续复用。 |
| 等待用户审看 | 正常等待阶段；完成对应卡片后继续。 |

## 验收范围

后台 runtime 的受控回归使用真实 SQLite/画布保存、受保护的保存态读取与回执、真实用户消息确认入口、原生方案 CAS、审核和素材工作包。无台词视频及两位本地系统声音依次发声的同一视频均通过实际原生编译/FFmpeg 导出；识别供应商和模型推理使用受控替身，句词时间是夹具证据，不代表真实 ASR 质量。

声音来源改造另有几条确定性回归：测试提交明确的素材工作包供来源校验，再把两句共用的视频通过原生命令绑定，附上手工时间证据并用 FFmpeg 合成，检查主声音与独立配乐、覆盖画面的可选原声。Agent 来源的联通测试从原生方向绑定、手动审批、起草 action 进入任务 runner，使用模型文本替身保存方案，再由任务结算、`production_event` 和观察器保存 commission 并调用通知与续接；坏 JSON 不发布方案成功消息。测试构造了画布确认回执并记录 coordinator 调用，没有执行真实浏览器按钮或 Agent 消息投递。另有独立测试分别核对保存态结算及失败与 `saved:plan-ready` 事件键的消费边界。真实对白与口型、浏览器播放、画布按钮完整旅程和用户项目成片仍须验收。

项目专用 Codex 的 Chrome 实机记录由主任务另行写入[后台验收记录](../../experiments/reference-director-background-acceptance.md)。在该记录补齐前，分析后摘要、确认后读改方案、断线恢复、编辑冲突及初始化后的实际 backend/二进制/8781 请求均为待实机验收。此前手动方向确认与方案自动保存的页面证据不能替代这次后台 Codex 验收。付费供应商整片制作、声音内容自动审听和整段运动自动判断为未验证；这些品质项仍需实际用户审看。

## 后台容量与故障诊断

同一项目 home node 的 API/worker 必须共享 `NOVELVIDEO_STATE_DIR` 下的
`reference_remix_continuations.db`，不能为每个进程设置独立目录。后台 Agent 续跑使用该
SQLite 的真实 run owner 租约进行原子准入；`DRAMACLAW_REFERENCE_BACKGROUND_GLOBAL_LIMIT`
默认 `4`，`DRAMACLAW_REFERENCE_BACKGROUND_TENANT_LIMIT` 默认 `1`。这是现有任务队列、
模型网关与 chat 锁之外的额外最大并发，现有更低限制仍然生效。配置由宿主部署环境提供。
租户命名空间使用已解析 `ProjectContext` 的 `(owner_type, owner_id)`，组织共享项目按组织
计数，同一用户的多个项目共用一个额度；请求者身份、私有画布和源版本仍分别验证。

容量不足会保留 `analysis_ready` 和原阶段凭据并提示等待，不调用模型、不标记阶段失败。
等待用户、等待媒体任务与无变化观察不持有模型额度。真实续跑的额度随 run owner 每
15 秒续租，正常结束、取消和 owner 释放会删除额度，死亡进程的额度随 60 秒 run 租约
过期回收。服务重启继续使用原任务和事件指纹，不能据此重发付费任务。

生产记录和活跃记录以持久化 cursor 每页最多 100 条轮转；每页至多 8 个生产证据检查，
单个检查等待上限 5 秒，同一请求者/项目/画布的任务与历史快照在该页内共用一次。
快照不跨请求者、项目或扫描页缓存，每条记录仍先执行权限与当前源校验。后台活跃检查
初始 2 秒、生产观察初始 5 秒，无变化后逐步退避到至多 30 秒并加入抖动；活跃调度仅保存
最近 1000 条状态指纹，并限制每进程最多 128 个 run worker。真实用户确认直接唤醒原 run；
同进程已实际保存且 task-id 验证通过的任务完成可以立即提示调度器重新扫描，提示本身
不能推进阶段。独立 worker 进程间不新增消息总线，提示丢失或异进程完成仍由持久化轮转
扫描恢复；记录较多时需计算轮转页数造成的额外延迟。这些后台退避不影响浏览器独立的
45 秒 ownership/presence 租约续租。

开启相应模块 DEBUG 日志可按 run/turn、bridge digest、来源、版本、投递次数、耗时与错误
类型关联消费记录。新日志不输出 executor token、凭证、签名 URL 或私人正文。桥接 inbox、
producer 和 presence 的过期清理每次最多 200 条，过期时间有索引；实际过期条件和作用域
筛选先于分页，历史 receipt 的安全校验保持有效。排查时先确认 home node、共享状态目录、
当前源版本与真实 receipt，再检查后台额度占用和队列等待，不能将观察轮询当作模型调用。

受控容量回归：`uv run pytest tests/test_reference_observer_scheduling.py tests/test_reference_background_capacity.py tests/test_reference_director_journey.py -q`。
其中 100 租户 / 1000 记录使用本地 SQLite、受控任务快照和模型替身，不产生付费媒体。
机器与本次查询/扫描数量、调度耗时及额度峰值记录在实施报告中；这些结果验证有界与轮转
公平，不能直接推断线上 QPS、真实模型耗时或大型项目完整任务列表的读取成本。
