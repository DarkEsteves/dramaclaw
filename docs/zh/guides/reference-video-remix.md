# 参考视频改编：画布操作与本地运行

这条流程把参考视频拆成可核对的事件，再生成新主题脚本。操作者在脚本中决定每段使用人物口播视频、独立旁白还是原声视频，并指定人物、产品、场景与补充画面。画布按实际选中的片段声音编译时间轴，再生成合成清单与 MP4。真实语音的生产准确率仍需代表性样片与人工边界验收，详见[实施状态](../../experiments/reference-video-remix-implementation-status.md)。

## 开始前准备

- 项目环境已经执行 `uv sync --group dev`，机器上可用 `ffmpeg` 和 `ffprobe`。
- 已按[配置模型供应商](../getting-started/configuring-models.md)接入可用的文本模型网关。原片结构分析、按蓝图生成脚本和 B-roll 规划需要文本模型。
- 需要自动转写或“按脚本对齐”时，另行准备独立 WhisperX Python、离线模型缓存和 NLTK `punkt_tab`。仓库不附带这些权重，也不会在任务运行时下载。
- 本地开发直接在仓库根目录运行 `scripts/start-remix-speech.sh`。看到 `Speech engine is ready` 后保持该终端运行；另开终端启动前端。完整变量和探活方式见[本地语音引擎试运行](../../experiments/reference-video-remix-speech-setup.md)。
- 当前输出固定为 H.264 MP4、1080×1920、30 fps，带 AAC 音轨，成片最长 60 秒。逐段流程的总时长由各段实际视频或旁白素材决定；整段旁白流程由旁白决定。
- 逐段口播需要支持**原生声音**的视频生成模型。选择人物、产品、场景参考后，视频节点会使用全能参考模式；所选模型还需支持该模式。没有相应模型时，可以上传已完成的带声视频。时间轴对齐仍依赖已配置的 WhisperX。
- 单文件上限 500 MiB。视频支持 `.mp4`、`.mov`、`.mkv`、`.webm`；音频支持 `.mp3`、`.m4a`、`.wav`、`.aac`、`.ogg`、`.flac`；图片支持 `.png`、`.jpg`、`.jpeg`、`.webp`。

本地开发可用下面两个终端启动：

```sh
# 终端 1：带离线 WhisperX 的 API
scripts/start-remix-speech.sh

# 终端 2：前端热更新
cd frontend
pnpm install
pnpm dev
```

浏览器打开前端地址，新建或进入一个项目的自由画布。执行写入和提交的账号需要该项目的 editor 权限；分布式部署还要求请求落到项目 home node。

## 从空白画布完成一次改编

1. **上传并分析参考视频。** 在自由画布点左下角 `+`，添加“视频”节点并上传文件。选中视频节点，点顶部 `分析原片`。系统会自动连出“原片拆解”节点；顶部按钮会显示 `继续改编 · 等待原片分析`，完成后变为下一步。
2. **核对拆解并生成脚本。** 在“原片拆解”的事件列表中查看时间、画面证据、台词证据和模型判断。每个事件下方都直接显示 `叙事作用` 和 `核对状态`，它们不在 `参考蓝图与分析设置` 的折叠区里。没有疑问时可点列表顶部的 `全部标记为已核对` 一次确认所有剩余项目；有疑问的事件先选为 `已核对，保留不确定`，批量确认不会覆盖它。仍有 `待核对` 的事件时不能生成脚本。整体保留/替换规则需要调整时再展开 `参考蓝图与分析设置`。完成后点 `生成改编脚本`，或点顶部 `继续改编 · 确认分析并生成脚本`。蓝图在这一步自动保存版本，不需要额外的“保存蓝图”动作。
3. **确定每段的做法。** 在“改编脚本与语义区间”填写新主题并生成台词。系统按说话者拆成表演段落；你可以逐段选择 `人物口播视频`、`独立旁白` 或 `保留原声视频`。台词、模式与素材绑定会自动保存。修改台词后，受影响的表演片段需要重新选择。
4. **换人物、产品、场景。** 对口播段落，在对应的“人物参考”“产品参考”“场景参考”里选择现有素材，或点 `上传`／`生成` 创建参考节点。还可选择声音参考、裁出的原片镜头参考。点 `创建口播视频节点` 后，在该节点检查提示词、模型和参考连线，生成带声音的视频，也可选择已有视频。原声模式可选择原片或上传另一段带声音的视频。只有真正带音轨的视频才能作为口播片段。
5. **处理独立旁白和 B-roll。** 选择独立旁白时，点 `创建旁白节点`，在音频节点生成或上传声音，再为这一段选一张图片或一段视频作为主画面。选中脚本里需要覆盖画面的词句，添加语义事件；规划 B-roll 后，对必需事件生成或上传补充画面。补充画面覆盖在主画面之上，不能代替人物声音。素材完成后会自动绑定到脚本版本。
6. **编译表演时间轴。** 所有段落都有实际素材后，点 `继续改编 · 按表演片段生成时间轴`。后台对每段采用的声音与对应台词对齐，合并为连续时间轴。片段媒体或脚本变更后必须重新编译。语音引擎未配置时，界面会明确提示配置需求。
7. **准备清单并导出。** 点 `继续改编 · 创建成片清单`。合成清单使用每个口播视频自带的声音、独立旁白段落的音频、已选主画面与 B-roll。确认没有未解析事件或冲突后导出 MP4；上游素材变更时先更新清单。

若要沿用一条完整的旁白音轨，在脚本面板点 `改用整段旁白流程`。此模式仍按“创建旁白节点 → 按脚本对齐 → 生成语义时间轴 → 选择成片背景／主画面 → 合成”的顺序操作。点 `按台词拆段` 可重新进入逐段表演流程。

顶部 `继续改编 · …` 始终定位到这条链路的下一项未完成工作；需要回改时，也可以直接选中对应节点使用节点内按钮。等待中的任务无需反复点击，刷新页面后会按原任务 ID 恢复检查。

## 常见阻塞与恢复

| 页面提示 | 处理方式 |
| --- | --- |
| `当前视频没有声音，无法转写`、`没有识别到人声` | 参考片无音轨时不要对它点“转写”；完成脚本后在旁白节点生成或上传清晰人声。文件有音轨但仍无结果时，先确认语言和实际人声，再点 `重新转写` 或 `按脚本对齐`。若提示语音引擎未配置，使用 `scripts/start-remix-speech.sh` 启动并检查探活。 |
| `脚本与音频不一致` | 在“转写与对齐”节点点 `校对台词`，让保存的脚本与实际发音逐字一致；或重新录制/生成旁白。随后点 `重新对齐`。不要用“保存校字”把增删台词伪装成同音纠错。 |
| `补齐必需 B-roll`、`素材已变化` | 回到脚本编辑面板，为对应语义区间生成或上传补充画面；完成后检查绑定状态。素材被替换或删除后需绑定当前版本。 |
| `台词已改变，请重新标记这个区间` | 在改编台词中重新框选完整词句，添加事件并删除失效区间；修改会自动保存。 |
| `语音对齐服务尚未配置` | 按[本地语音引擎试运行](../../experiments/reference-video-remix-speech-setup.md)启用 WhisperX 并确认探活，再编译时间轴。 |
| `上游已变化，更新清单`、`预览已过期` | 点 `更新清单`。若出现手工修改冲突，逐项选 `保留手工值` 或 `采用上游值`；无法安全保留时采用上游值。保存清单修改后重新导出；导出完成后再确认状态变为 `预览与导出一致`。 |
| 导出一直处于恢复确认 | 先点 `重新检查任务`。确认旧任务已失败或结果已过期后，才点 `强制重新导出`；不要刷新后立即重复提交。 |

## 操作者交接检查

交付演示前确认：参考拆解事件均已核对；每段采用的视频或旁白与脚本版本一致；口播视频确有音轨；独立旁白段落有主画面；每个必需 B-roll 都连接实际素材；合成节点没有未解析事件或冲突；下载的 MP4 为 1080×1920/30 fps，声音来自已选片段。

这份检查只证明画布链路和固定媒体产物可用。上线真实语音前，还必须补齐中英文各至少 100 个人工边界、授权素材清单、权重许可证，以及目标机器上的 P95、耗时、内存和并发数据。
