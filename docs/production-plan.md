# 作品方案与视频合成

作品方案是画布上可由人或 AI 编辑的作品源数据。它以 `production_plan.v2` 保存目标、画幅、帧率、叙事段、台词、素材版本，以及画面、声音和字幕在成片中的关系。原片分析可以提供创作参考，但不规定必须按每句台词或原片每个事件分段。同一个原片拆解节点可以新建多个相互独立的作品方案；已有方案直接从各自节点编辑。

## AI 起草与时间约定

AI 起草在同一个后台任务内依次整理叙事与台词、安排画面与声音，再由程序组装并校验同一份可编辑作品方案。前两个阶段的结果仅供该任务内部使用；只有完整校验并保存后才产生正式方案。模型决定创作内容，程序只补齐有唯一含义的格式字段。新草稿中的字幕 `kind=subtitle` 可省略 `role`，保存前补为 `dialogue`。该补全只作用于这次草稿，不修改用户已保存或手工编辑的方案。

段落的 `duration_frames` 是估计时长。未有实际素材时，台词默认不填 `start_frame/end_frame`；如果填写，二者都按所属段落内的帧数解释。纯估计、自动时长的段落若出现越界估计，可在不改变台词内容的前提下退回待校准时间；固定时间、真实语音证据和用户明确的成片时长继续严格校验。后续从视频或 SRT 取得的时间，仍按现有校准和合成规则处理。

完整段落可用 `beat` 的 `edge=start/end` 锚定。新草稿的 `beat` 锚点如果有明确的 `offset_frames` 而省略 `edge`，该偏移约定为从段首计算，保存前补 `edge=start`；引用的段落必须存在且偏移处于段落范围内。其他锚点仍须写明对应边界。时间倒置、引用不存在或证据伪造不会被自动修复。

起草仍通过画布原有动作执行与确认流程。模型返回、草稿格式补全、方案保存和审核是不同状态；生成成功以真实保存回执为准。正常起草按固定顺序最多发出两次模型请求，每阶段一次；任何阶段失败即停止，不主动重试。当前默认总输出预算为 16384 token，分给结构与台词 4096、画面与声音 12288，可由现有环境变量覆盖。任务中心仍显示一个任务，内部阶段结果保存在对应 operation 的 `draft-stages/<operation_id>/<task_id>/` 目录以便排查，不进入方案 `plan_ref`。用户明确发起的手动重试会重新执行两个阶段。

## 画布流程

1. 在作品方案编辑目标、段落和台词，也可创建「命名范围」，把起止点指向段落、台词或已对齐的词。首次进入视频合成时，旧 `production_plan.v1` 会保留原修订并显式迁移成 v2。迁移后仍从原方案节点的「方案与素材」编辑台词、画面和声音；「台词主线」是同一编辑器的另一视图，修改已校准台词会使旧逐词时间失效，需重新校准。
   有台词且已绑定发声素材时，先为每句选择人声轨或带声音的视频并点「校准台词时间」。人声／旁白轨会提示关联台词；视频仅有音轨并不能证明其中有人说话，需由用户明确选为该句发声素材。多位说话人可以共用一个带原声的主画面视频：只提交一次完整素材识别，再按方案中的台词顺序拆成每句各自的逐词时间和证据引用，画面仍只放置一次，无需复制视频或另建声音轨。系统用 NewAPI `audio-transcribe` 保存可核对的逐词产物；不会按预计段落时长截断识别。录音与整组台词不符时留在方案中提示复核。无语音段落直接按画面和节目时间编排；当前发声源经校准确认为无语音时，也可按估算时间继续。
2. 有待校准台词时，方案底部显示数量并定位第一句，暂不创建视频合成节点。发声素材的裁剪范围若在方案中无法校准，可先进入视频合成调整范围，再返回方案校准。「进入视频合成」在语音时间就绪后创建或复用直接相连的 `videoComposeNode`，打开原有全屏合成器入口。旧 v1 方案首次迁移后若有待校准台词，会先停留在新版方案编辑器。新流程不再创建「成片编排」节点；历史编排与合成节点会通过原连线识别。若旧清单有尚未保存的修改或不能无损转换的手动覆盖，迁移会停止并提供「查看原视频合成」入口，避免丢失旧编辑。
3. 未绑定的画面和声音作为轨道占位显示。可从左侧选择已完成的画布素材，或者创建上传、生成图片、视频、声音节点；从选中条目创建素材时，生成完成后自动回填该条目。绑定时建立「素材 → 作品方案」边并记录媒体 SHA-256 与项目路径。屏幕文字、问题卡片等内置图形效果不需要绑定素材，可在作品方案或合成器中直接添加。
4. 合成器顶部同时显示段落、台词、逐词位置与命名范围。选中画面、声音或字幕，可将其起止点绑定到同一命名范围；调整词或范围后，相关条目一起移动。拖动、拆分、调整布局和声音属性仍写回同一份方案并串行自动保存。可从选中条目返回作品方案对应位置。并发冲突按稳定 ID 列出具体字段，可逐项采用远端值后将当前草稿另存为新方案。
5. 左侧「素材版本」列出已绑定画布节点、可用时的节点修订、媒体路径及内容哈希；「任务记录」只列出本合成节点或精确方案修订相关的操作。素材库原有绑定和拖放入口继续可用。
6. 「检查素材」定位缺失、版本变化和时间问题。已保存且检查通过时，可点击「核对导出画面」按当前帧请求服务端的真实渲染画面，与浏览器轨道预览并排比较。它只在点击时渲染一帧，不随拖动播放头持续生成。导出固定到已保存的方案修订，编译 `composition_manifest.v2` 并交给现有渲染任务。旧 MP4 保留为旧版预览，直到新结果确认完成。

手动视频合成项目继续使用原来的合成草稿和编辑器功能；`remix_script.v1` 与旧 manifest 不强制迁移。

## v2 作者数据

- `output`：宽、高、帧率分子和分母、背景色。新方案没有固定竖屏、30 fps、60 秒或段落数上限。H.264 输出需要偶数宽高；无效规格会明确报错。
- `beats` 与 `turns`：叙事段可包含多句台词、多人，或完全没有台词。未对齐的台词时间只是估算；有逐词时间时保留其稳定 ID。
- 默认段落按发声素材实例的实际可播放时长排布。一份视频中的多句台词共享同一实例，只占一次节目区间；素材内的停顿也保留。`duration_frames` 是素材未就绪时的估算；无语音段落和用户选定的固定时长段落继续使用它。裁剪或更换发声素材后重算语义锚点，手动设置的绝对节目帧位置保留。旧 v1 迁移生成的段落素材改为段落相对锚点，避免后续段落改长时仍停在旧全局帧。
- `turns.speech_timing`：可选的发声条目 ID、台词和媒体哈希、精确逐词证据引用，以及词在源素材中的时间与文字位置。它属于已保存方案的上游引用。移动发声条目或调整播放速度时，词、台词边界、字幕强调和引用这些词的画面会重新投影到节目时间；改台词、换素材或改变源片裁剪范围后，旧证据标为失效。只有依赖失效词锚点的条目需要重校准，纯画面作品仍可导出。
- `selections`：有名称与稳定 ID 的语义范围。起止点引用节目帧、段落、台词或词；绑定的多个条目共享这对边界。无效或越界范围会在投影中列为问题，并阻止编译。旧 v2 文档缺少此字段时按空列表读取。
- `resources`：项目相对媒体路径、SHA-256、画布节点 ID、媒体类型和时长。远程 URL 或任意本地路径不能直接作为资源。
- `placements`：跨段的主画面、叠加画面、图形效果、人声、旁白、音乐、音效与字幕。每项有稳定 ID、轨道、节目时间锚点，可选源素材入出点、变速、布局、透明度和音量。语义锚点可以指向段、台词、词、命名范围或其他条目的起止边界，拖动时保留锚点并修改偏移。
- `provenance`：上游蓝图或迁移来源的精确修订。

## SRT 台词主线

作品方案中的 `speech_takes` 表示一次发声素材播放实例，`speech_cues` 表示带稳定 ID 的句级时间。两个人在同一视频里说话时，校准任务识别完整素材一次，各句保留独立源时间，视频与原声各播放一次。主线按实际素材时间投影到节目时间；后续段落随素材长度顺接。无台词段落没有强制 SRT 或 ASR 门禁，混合作品按段落分别处理。

编辑器的「台词主线」可从已绑定的发声实例导入源素材 SRT，预览并明确指定每行对应哪句台词；也可人工修订源时间。确认后先保存项目内的 `speech_cue_evidence.v1`，再将其引用写回同一份 `production_plan.v2`。导入的是句级时间，不会伪造逐词证据。ASR 逐词证据继续保存在 `word_timeline.v1`；重新识别无法唯一对应旧词时，相关 cue 进入复核。修改真实台词或更换素材会使原校准失效。

旧方案中的逐词记录可供回看，但只有来源、台词、媒体版本与完整素材范围都能验证的记录才升级为就绪 cue。早期按预计时长截断过的识别会显示待复核，用户可对完整素材重新校准；旧记录不会被静默改写或伪装成完整识别。

每个 cue 行可安排字幕、图形、叠加画面或切换主镜头。画面、字幕和效果的起止点引用 cue、词或命名范围，节目位置由投影计算。合成器显示同一组 cue 和轨道，改变条目锚点、位置或样式仍自动保存到方案；导出读取精确的方案修订。SRT 导出使用节目时间，导入则明确使用所选素材的源时间。字幕显示文字可单独修改，不反改台词证据。

新格式沿用方案自选宽高、帧率与时长，未限制竖屏、30 fps 或 60 秒。当前图形效果使用已有原生模板，浏览器 HTML 动效留待后续设计。

未绑定方案允许保存并进入合成器。投影接口返回条目级问题；正式导出要求对应媒体存在、哈希匹配、画布绑定仍为当前版本，且时间和源范围有效。提交 v2 渲染时服务端再次读取已保存画布，核对方案和清单修订、直接连线，以及每个已用素材节点的媒体版本；旧的 `render_manifest` 动作不能绕过此检查。编辑时的轨道预览可显示未保存草稿；正式导出只读取保存修订，未保存的局部修改不会进入 MP4。

## 可供代理调用的稳定接口

以下路由都在 `/api/v1/projects/{project}/freezone/remix` 下，受项目角色和 home node 检查约束：

| 动作 | 路由 | 关键输入 |
| --- | --- | --- |
| 保存方案 | `POST /artifacts` | `schema: production_plan.v2`、完整 payload、精确 `upstream_refs` |
| 按修订修改 | `PUT /artifacts/{id}` | `expected_revision`、完整 payload、精确上游引用；冲突返回 409 |
| 读取修订 | `GET /artifacts/{id}?revision=n` | 不省略修订号 |
| 比较最新版本 | `GET /artifacts/{id}/latest` | 冲突后读取远端；不静默覆盖本地草稿 |
| 迁移旧方案 | `POST /production-plans/migrate` | `{plan_ref:{artifact_id,revision}}` |
| 检查可编排性 | `POST /production-plans/project` | 相同精确 `plan_ref`；返回条目状态和 `issues` |
| 核对一帧 | `POST /production-plans/preview-frame` | 精确 `plan_ref`、节目 `frame`；仅在素材哈希与时间校验通过后返回 PNG |
| 编译 | `POST /production-plans/compile` | 精确 `plan_ref`；返回可重建的 manifest |
| 固定媒体 | `POST /media/attach` | 项目相对 `media_path`；返回哈希与媒体探针 |
| 校准台词时间 | `POST /actions` | `action: align_production_speech`，精确 `plan_ref`、`turn_id`、`take_id` 或旧版 `placement_id`、项目内 `media_path`；在 speech 队列生成 `word_timeline.v1`，方案接受后自动保存 |
| 提交渲染 | `POST /artifacts/{manifest_id}/render` | manifest 修订、幂等键、节点修订及画布关联 |

代理操作顺序与界面相同：读取最新方案 → 修改稳定 ID 对应条目 → 以 `expected_revision` 保存 → 检查缺项 → 编译 → 创建 `composition_manifest.v2`，把同一方案修订放进 `source_versions` 和 `upstream_refs` → 提交渲染 → 按现有 operation 确认结果。manifest 发布时服务端重新编译源修订并逐项比对，拒绝伪造或脱离方案的清单。代理无需依赖按钮坐标、Hypit SVML 语法或咖啡样片的固定结构。

### 内置图形效果

作品方案中的 `graphic:effect` 是无需媒体文件的独立条目，包含模板、文案、可选重点词、文字色、底色、强调色、入退场帧数和位置。当前模板为 `question_card`（带底色的问题卡片）、`keyword`（无底色的强调文字）和 `title_bar`（顶部标题条）。入场可选直接出现、淡入或缩放出现；退场为淡出。AI 起草可以生成这些结构化参数，用户在作品方案和合成器中仍可编辑。图形时间可锚定到段落、台词、词或命名范围；无台词作品可用节目帧锚点。

编译后图形保存在 `composition_manifest.v2` 的 `graphic_events`，与画面、声音、字幕一起进入现有 FFmpeg 合成。轨道播放是即时近似预览；「核对导出画面」按同一清单渲染指定帧，正式导出使用同一套图形参数。旧清单没有 `graphic_events` 时按空列表处理。模板、颜色、文本和动画帧数受到契约校验；这条路径不执行任意 HTML 或 JavaScript。浏览器 HTML 动效和注册效果组件属于后续阶段。

逐帧核对接口按项目隔离缓存，缓存键包含方案修订、完整编译清单和帧号；即使命中缓存也会重新核对素材哈希。服务端最多同时渲染两帧，每个项目保留最近的 40 帧缓存，避免预览请求无界占用机器资源。浏览器中的即时播放仍是交互预览，涉及 FFmpeg 字幕与混合等细节时，以「核对导出画面」和正式 MP4 为准。
